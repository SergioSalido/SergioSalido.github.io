HotelApp

Aplicación de escritorio creada para consultar habitaciones y registrar reservas del Hotel Sol. La interfaz muestra datos reales almacenados en XML y permite comprobar su disponibilidad, tipo y precio por noche.

Java 17JavaFX 21FXMLXML / DOMMaven
Ver funcionamiento, código y capturas ↗

Proyecto realizado por mí en la asignatura Desarrollo de Interfaces (2.º DAM) · Octubre de 2026.

Consulta de habitacionesSelección desde un desplegable, mostrando número, tipo, estado y precio por noche.
Registro de reservasFormulario con nombre del cliente y fechas de entrada y salida mediante calendarios.
Persistencia XMLLectura y escritura del archivo reservas.xml con DOM; al reservar, se guarda la reserva y cambia el estado a ocupada.
ValidacionesBloqueo de reservas en habitaciones no disponibles y comprobación de nombre y fechas.

Cómo desarrollé la aplicación

PROCESO · ESTRUCTURA Y TECNOLOGÍAS

Organicé el proyecto separando la interfaz, las clases de datos y la lógica de las reservas. La información se guarda en un archivo XML local, sin depender de una base de datos externa.

  1. Preparación con Java y Maven

    Configuré el proyecto en pom.xml con Java 17, JavaFX 21 y el plugin de Maven que permite arrancar la aplicación mediante mvn javafx:run.

  2. Diseño de la interfaz

    Utilicé reservas.fxml para definir la ventana: selector de habitaciones, botón de consulta, campo de cliente, calendarios de entrada y salida y botón para guardar. Main.java carga esta vista.

  3. Organización de los datos

    Creé Habitacion.java para representar número, tipo, estado y precio, y Reserva.java para cliente, habitación y fechas. Las habitaciones y las reservas se almacenan en reservas.xml.

  4. Lectura del XML y consultas

    En HotelController.java usé DOM (DocumentBuilderFactory, Element y NodeList) para leer el archivo, crear una lista de habitaciones con ArrayList y mostrar sus datos al seleccionarlas.

  5. Formulario y validaciones

    Conecté los controles FXML a los métodos del controlador. Antes de reservar, la aplicación comprueba que la habitación esté disponible, que haya nombre y que las fechas sean válidas: entrada desde hoy y salida posterior.

  6. Guardado y comprobaciones

    Al confirmar, el controlador añade una reserva con código único y cambia el estado a ocupada. Para conservar el archivo, escribe primero en un temporal y después reemplaza reservas.xml. En el informe comprobé los casos 111 (disponible) y 101 (ocupada).

Así funciona por dentro

reservas.xml → lectura DOM → objetos Habitacion → interfaz JavaFX → consulta o reserva → guardado en XML.

Pruebas documentadas: habitación 111 disponible y habitación 101 ocupada. La interfaz y los resultados aparecen en las capturas del informe.

CAPTURAS REALES · EXTRAÍDAS DE MI INFORME
Próximas mejoras: búsqueda manual por número, aviso para habitaciones inexistentes y filtros para mostrar solo las disponibles. Actualmente el desplegable permite consultar habitaciones registradas. La disponibilidad se basa en su estado, no en el solapamiento de fechas.

HotelApp2 · Filtros de habitaciones

Segunda versión del sistema de consulta de habitaciones de Hotel Sol, desarrollada junto a dos compañeros a partir de las ideas de nuestros HotelApp individuales. Incorporamos filtros combinables y una búsqueda por número más completa para consultar la disponibilidad con mayor facilidad.

Java 17JavaFX 21FXMLXML / DOMMavenTrabajo en equipo
Ver mejoras, funcionamiento y galería ↗

Proyecto colaborativo de 2.º de DAM · Octubre de 2026. Reunimos distintas soluciones de HotelApp en una aplicación común.

Filtros combinablesFiltrado por estado (todos, disponible, ocupada o mantenimiento), capacidad mínima y accesibilidad.
Actualización inmediataLa tabla se actualiza al modificar el ComboBox, el Spinner o el CheckBox, utilizando FilteredList.
Búsqueda por habitaciónPermite buscar por número, seleccionar la fila y mostrar si está disponible, ocupada, en mantenimiento o no existe.
Datos y contadorLectura de reservas.xml con DOM, información tabulada y contador de habitaciones visibles sobre el total.

Cómo funciona por dentro

ESTRUCTURA DEL PROYECTO

La vista vista.fxml define la tabla y los controles. Habitacion.java modela cada habitación; HotelController.java carga el XML y combina los filtros con eventos de JavaFX. Main.java inicia la aplicación.

Flujo de datos

reservas.xml → DOM → ObservableList<Habitacion> → FilteredList → TableView.

Pruebas: búsqueda de la habitación 137 (inexistente), búsqueda de la 120 (disponible) y filtro adicional para mostrar solo habitaciones accesibles. Cuando una habitación encontrada no cumple los filtros activos, estos se limpian para poder localizarla en la tabla.

GALERÍA DE CAPTURAS REALES · HOTELAPP2
Alcance de esta versión: consulta y filtrado de habitaciones a partir de un XML local; no incorpora un formulario de nuevas reservas ni comprueba disponibilidad según fechas.

No Respondas · Ala Norte

Beta de videojuego de terror y supervivencia en primera persona ambientado en el Instituto Valdemar. Creado con JavaScript y WebGL, y adaptado a Windows mediante Electron, con el apoyo de herramientas de inteligencia artificial durante su desarrollo técnico.

Desarrollo asistido por IA. He utilizado herramientas de IA generativa como apoyo para programar e implementar las partes más complejas del juego. Mi aportación ha estado en plantear la idea, decidir cómo quiero que funcione, probar los resultados y orientar las mejoras.

Estado del proyecto: beta jugable (versión 0.3). Es una prueba en desarrollo, con funciones sujetas a cambios y mejoras.

JavaScriptWebGLElectronHTML/CSSIA asistida

La versión Ala Norte incluye seis salas conectadas, doce objetivos, puzles interactivos, inventario, linterna con batería, sistema de escondites, guardado de progreso y controles configurables.
